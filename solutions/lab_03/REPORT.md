# Вопросы и задания
### 1\. Зачем при создании SSH-ключа предлагается задать парольную фразу и от какой угрозы она защищает?
Парольная фраза нужна для шифрования закрытого ключа. Это защищает от кражи файла ключа (без парольной фразы им не воспользоваться) и от компрометации при потере устройства.
### 2\. Зачем при первом подключении по SSH клиент показывает отпечаток ключа сервера и просит подтвердить его? Что произойдёт, если отпечаток изменится?
Отпечаток ключа сервера нужен, чтобы пользователь знал, к какому серверу он подключается. При смене отпечатка покажется предупреждение и подключения не произойдёт.
### 3\. Если у двух пользователей одинаковые пароли, можно ли понять это по /etc/shadow? Почему?
Это можно понять, потому что для хэш каждого пароля содержит случайную соль, которая будет разной даже у одинаковых паролей.
### 4\. Заполните таблицу: атрибут (r, w, x, suid, sgid, sticky bit), сокращённое название, значение для файла, значение для каталога. В таблице должно быть 6 строк.
| Атрибут | Сокращение | Значение для файла | Значение для каталога |
|---|---|---|---|
| read | r | Можно читать содержимое файла | Можно просматривать список файлов в каталоге |
| write | w | Можно изменять содержимое файла | Можно создавать, удалять и переименовывать файлы внутри каталога |
| execute | x | Можно запускать файл | Можно входить в каталог и запускать файлы оттуда |
| SUID | s | Файл выполняется с правами владельца | Не применяется | 
| SGID | s | Файл выполняется с правами группы владельца | Новые файлы и подкаталоги наследуют группу владельца |
| Sticky bit | t | Не применяется| Удалять и переименовывать файлы может только владелец или root|
### 5\. Почему для удаления файла нужны права на каталог, а не на файл? Какие изменения вносит установка sticky bit на каталог?
Каталог - это таблица, поэтому удаление файла это удаление записи из таблицы. При установке sticky bit удалять и переименовывать файлы может только их владелец или root.
### 6\. Приведите команду setfacl, которая даёт конкретному пользователю все права на файл, не делая его владельцем и не добавляя в группы. Как решить с помощью ACL задание 3 из Части 3?
`setfacl -m u:u4:rwx файл`

mkdir /DATA/sec2
chmod 700 /DATA/sec2
setfacl -m u:u4:r-x /DATA/sec2
setfacl -m u:u5:r-x /DATA/sec2
chown u1 /DATA/sec2
### 7\. Чем различаются su, su - и sudo? Почему в Debian для повседневной работы рекомендуют sudo, а не пароль root?
su сохраняет окружение текущего пользователя, su - полностью имитирует вход root, sudo выполняет одну команду от имени пользователя. Работать с sudo безопаснее и это позволяет просматривать кто выполнил ту или иную команду.
### 8\. Удалось ли вам обойти ограничение sudo из Части 5, Блок А? Почему правила с подстановочными знаками в sudoers считаются опасными?
Ограничение обойти не удалось. Опасно, потому что трудно предсказать все возможные комбинации аргументов.
### 9\. Чем отличается SIGTERM от SIGKILL? Какой из них процесс может перехватить?
SIGTERM можно проигнорировать, а SIGKILL нельзя. Перехватить можно только SIGTERM. 
### 10\. Что происходит с процессом, запущенным через &, при закрытии SSH-сессии, и почему nohup меняет это поведение? Почему у процесса с nohup PPID после этого стал другим?
Всем процессам отправляется сигнал SIGHUP и они завершаются. nohup даёт процессу команду игнорировать SIGHUP. Когда сессия закрывается, то bash завершается, поэтому дочерний процесс script32 становится "сиротой" и linux переназначает его родителем процесс с PID 1.
### 11\. Что такое зомби-процесс? Можно ли его убить командой kill -9 и почему?
Зомби-процесс - это процесс, который завершил выполнение, но его запись в таблице процессов ещё не удалена. Его нельзя убить командой kill -9 потому что зомби уже мёртв. Чтобы его завершить нужно убить родительский процесс. 
### 12\. Чем отличается вывод sshd -T от строк, найденных в sshd_config через grep? Приведите пример параметра, у которого они различаются.
sshd -T показывает итоговые значения параметров, выводя все имена в нижнем регистре. 
Пример: 

grep -i port /etc/ssh/sshd_config → #Port 22
sshd -T | grep port → port 22
### 13\. Какой риск возникает, если владельцем исполняемого файла будет root и на этот файл будет установлен suid?
Любой пользователь, запустив такой файл, получит права root на время выполнения.
